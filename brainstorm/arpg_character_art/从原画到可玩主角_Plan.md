# 从四视图到可玩主角：制作范围与验收

日期：2026-10-22。本文区分本轮已经实际完成的工程工作、需要后续验收的质量，以及正式 3A 制作需要投入的工作。最终运行结果以 `Artifacts`、`Saved/Verification` 和工程内资产为准。

> 公开版阅读说明：本目录仅发布流程文档。文内“本地工程”路径用于定位原工程中的源资产、代码和验证证据，相关文件及截图未随文发布；外部链接指向公开资料。版本、测试结果和资料核查日期均保留原记录，不表示在本文上传时重新验收。

## 目标与当前基线

目标是一名与 `Producer_Ref` 四视图一致的男性写实主角，在 UE5 场景里用《神秘海域》《最后生还者》式的第三人称视角行走。参考的是镜头与身体的控制关系；这些作品的引擎、动画数据与生产管线不能直接复制进本项目。

本机可运行的安装版是 **UE 5.7.4，CL 51494982**。原技术研究中的 **5.8.3** 是另一份源码目录的版本标识，本轮没有把它当作已运行环境。工程、API 和编译验证以 5.7.4 为准。

本轮采用四视图重建、自动蒙皮、Blender 骨架修复、UE IK Rig 重定向、CharacterMovement、Enhanced Input 和 SpringArm。它形成可继续生产的角色与 3C 基线。它不等于已经完成影视级主角。

## 一张原画之后还有多少工作

下面是**本项目的初步工作量估算**，不是行业统一报价，也不是交付承诺。假设一名主角、一套复杂服装、PC 单机、常规第三人称近中景，没有战斗、攀爬、过场表演和完整面部系统。使用成熟工具，但需要可交付的原画还原与形变质量。

| 工序 | 交付内容 | 估算人日 |
|---|---|---:|
| 设计消歧与比例锁定 | 正侧背比例、材质拆分、隐藏部位、装备分件、身高和镜头距离 | 3–6 |
| 人体与头部高模 | 解剖、脸部辨识、手部、可近看的体积与细节 | 8–15 |
| 服装、铠甲与附件 | 衣物层次、真实厚度、缝线、硬表面、披风、穿插处理 | 10–20 |
| 拓扑、UV 与烘焙 | 变形友好拓扑、材质分区、法线/AO、纹理密度 | 6–10 |
| 皮肤与服装材质 | 清洁 PBR、皮肤散射、布皮金属的独立响应、近景 lookdev | 8–15 |
| 头发与毛领 | Groom 或发片、分束、发际线、LOD、光照与运动表现 | 5–10 |
| 骨架、蒙皮与修形 | 手指、肩肘、髋膝、衣甲分层、极端姿态、纠正形变 | 8–15 |
| 基础移动动作 | 待机、慢走、快走/跑、方向、启动、急停、转身、重定向清理 | 10–25 |
| 3C 与动作逻辑 | 输入、镜头、加减速、转向、碰撞、聚焦、动画转换 | 5–12 |
| 地面接触与衣物 | 脚部 IK、坡面台阶、披风/毛发模拟和穿插修正 | 6–15 |
| 引擎整合与优化 | LOD、材质成本、阴影、显存、骨骼与物理预算 | 5–10 |
| 质量验证与返修 | 各镜头、帧率、输入方式、坏姿势、性能和打包测试 | 8–15 |
| **合计** | **一名主角与基础移动 3C** | **82–168 人日** |

多人工作可以重叠，但建模、拓扑、绑定、动作、最终整合存在先后依赖。3–5 名有经验的成员，首轮高质量可玩样片可按约 6–12 周规划；最终质量取决于评审返工，不能用“人日 ÷ 人数”简单推算。扫描底模、成熟动作库与现成服装会减少部分工序；本角色的长披风、毛领、多层铠甲会增加形变与穿插成本。

面部表演、口型、战斗、武器接触、攀爬、翻越、掩体、受伤、多套服装、平台适配和完整游戏内容另计。若要求近距离过场的影视级面部，应单独规划扫描/雕刻、表情拓扑、面部绑定、皮肤和眼睛材质、牙舌、表演采集及逐镜头修正。

AI 可以缩短初始体积与表面贴图的制作时间。它不会自动证明拓扑适合蒙皮、衣物分件正确、脚底接触可信、头发可用于近景，或原画细节已经被准确还原。

## 本角色的关键风险

1. 四张图是有透视的设计参考，不是严格一致的工程正交图。铠甲和肩部在侧面、背面存在遮挡；这些位置仍需要设计判断。
2. 长披风遮住下半身，自动绑骨可能把披风顶点分配给大腿或手臂。行走时应逐帧检查膝部、髋部和背部是否被拖扯。
3. 毛领和头发目前是网格与贴图表达。最终近景需要独立发束、合理透明/覆盖方案、正确阴影和 LOD。
4. 自动骨架缺少完整手指与面部控制。它能服务基础行走验证，不能承担抓握、对白和精细表演。
5. 一套烘焙纹理可能包含原画光照。最终材质需要分离固有色、金属度、粗糙度、法线与皮肤响应，在多种光照下验收。

## 工程里的控制设计

- WASD / 左摇杆：相对镜头的平面移动，斜向输入归一化。
- 默认步行约 175 cm/s；Shift / 左摇杆按下：跑步约 460 cm/s；Alt：慢走约 95 cm/s。
- 鼠标 / 右摇杆：镜头自由环绕，俯仰限制避免翻转。
- 按住右键 / 左扳机：聚焦过肩，收窄 FOV，身体朝向镜头方向。
- Q / 右肩键：镜头左右肩切换。
- Home：复位；Esc：退出演示。
- CharacterMovement 负责重力、胶囊体碰撞、台阶与坡度；SpringArm 球体探测负责镜头贴墙回缩。
- 位移、身体转向和镜头的插值使用帧间隔。默认没有强制镜头晃动，便于先评估动作与接触。

真实的影视化动作还需要启动/停止/转身覆盖、脚锁、步幅适配、身体重心、镜头引导、交互接触和表演数据。Motion Matching 是消费动作数据的系统，不会凭空生成缺少的动作。初期先让可解释的基线工作，再换入 Game Animation Sample 的数据与轨迹方案，能更清楚地衡量收益。

## 验收门槛

| 层级 | 验收方式 | 不足时的处理 |
|---|---|---|
| 可运行 | 编译成功；主角资产实际被加载；地图可进入 | 修正引用、导入、默认地图、骨架和构建 |
| 可操控 | 前后左右、90° 镜头相对移动、斜向速度、跑/慢走、聚焦、换肩、墙体与镜头碰撞 | 查看 `Saved/Verification` 的实际运行报告 |
| 动作可信 | 低速、启停、180° 转身、斜走和聚焦后退连续；脚无明显滑移 | 增加动作覆盖，修正重定向、步幅和 IK |
| 角色美术 | 正侧背与参考对比；近中远景；多套中性/侧逆光；肩髋极端姿态 | 回到源模型、权重、材质与发型修正 |
| 性能可交付 | 在确定分辨率与画质下记录 CPU/GPU 帧时间、显存、慢帧与打包表现 | 用 Unreal Insights、GPU profiler 测量后优化 |

自动输入测试能证明逻辑与碰撞，不能替代角色美术评审。截图能证明某一时刻的画面，不能替代持续帧率或脚滑测量。本轮没有用离线 Blender 渲染冒充引擎实机画面。

## 能力边界与扩展

### 已经可用

本机的 `.agents/skills` 含 Unreal C++、Blueprint、Enhanced Input、镜头、游戏资产和 Tripo 等技能。**Skill 提供工作方法；执行能力来自实际的程序、API、资源和授权。**本轮实际使用了 UE 编译器与编辑器 Python、Blender 后台 Python、Tripo CLI，而非仅生成说明文档。

`Source/Frontier3CEditor` 已增加项目专用的资源构建接口。普通编辑器资产、可调 C++ 属性、源 `.blend`、FBX 和导入脚本都保留在项目里，可以继续迭代。

### 最有价值的扩展方向

| 缺少的能力/资源 | 扩展方法 | 对本项目的直接作用 |
|---|---|---|
| 编辑器实时查询和事务编辑 | 给已验证的 UE Editor API 增加项目专用 MCP/本地服务；只暴露资产查询、导入、保存、构建和截图等明确接口 | 减少反复启动编辑器；能查询真实资产状态并回传结果 |
| 精细 DCC 操作 | 使用已有 Blender Python；复杂衣物可接入有合法许可证的服装工具或专业 DCC | 分离披风、衣甲、毛领，手工修正轮廓、拓扑和蒙皮 |
| 高质量动作数据 | 获取有许可的 Game Animation Sample、动作库、动捕数据，并建立 IK Rig 映射 | 增加启动、停止、转向、走跑过渡和交互动作覆盖 |
| 近景数字人表现 | 使用有授权的人体/头部数据、MetaHuman 或自定义高质量头部工作流 | 完善脸部、眼睛、皮肤、手指和表情控制 |
| 美术与动作评审 | 角色艺术家、绑定师、动画师参与；给出具体逐帧/逐镜头反馈 | 这是达到 3A 质量的生产投入，安装更多 Skill 不能替代 |

Codex 的可复用 Skill 可放在项目的 `.agents/skills/<name>/SKILL.md` 或用户 Skill 目录；MCP 则把外部服务的可执行工具接入 Codex。应先定义本项目需要的工具契约，再选择兼容本地 UE 版本的实现，不能假设任意社区 Unreal MCP 都支持 5.7 或具备完整 Blueprint/动画编辑能力。[OpenAI：构建 Skill](https://learn.chatgpt.com/docs/build-skills)、[OpenAI：MCP](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)。

若日后接入本地服务，CLI 注册形式为 `codex mcp add <server-name> -- <server-command...>`；HTTP 服务使用 `codex mcp add <server-name> --url <server-url>`。其中服务命令、端点与可调用工具必须真实存在。本文没有注册虚构服务，也没有改写用户的全局 Codex 配置。凭证只留在对应服务的本地凭证目录，不能写进仓库。
